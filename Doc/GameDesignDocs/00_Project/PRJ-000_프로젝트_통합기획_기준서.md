# PRJ-000 프로젝트 통합 기획 기준서

> **자동 사격 메카를 조종해 군도 전역을 고속으로 선행 강습하고, 적성 구획을 무력화해 작전 항로를 개척하며, 회수 장비와 소모품 기반 빌드 강화를 이용해 더 깊은 해역으로 진입할지 손실 전에 복귀할지를 판단하는 고속 Third Person View 로그라이트 익스트랙션 메카 액션.**

## 0. 문서 역할과 읽는 법

### 0.1 이 문서가 결정하는 것

본 문서는 프로젝트 전체의 **기획 기준과 Canon 문서 진입점**이다. 프로젝트 정체성·디자인 필러·핵심 플레이 루프·목표 경험, 프로젝트 수준의 기술 목표·MVP·리스크, 시스템 지도와 여러 Owner에 걸친 Open Decision을 소유한다.

### 0.2 이 문서가 결정하지 않는 것

세부 Gameplay 규칙·세계관 사실·알고리즘·데이터 구조·FSM·Physics/ECS 구현·최종 튜닝 수치는 해당 Owner Canon이 결정한다. 현재 Owner와 Canon 문서 지도는 아래 §10에서 관리한다.

---

## 1. 프로젝트 정의

### 1.1 프로젝트 개요

| 항목 | 현재 기준 |
|---|---|
| 장르 | 고속 Third Person View 로그라이트 익스트랙션 메카 액션 |
| 핵심 플레이 | 자동 사격 + 수동 장비 교체 + 3D 기동·포지셔닝 + 복귀 판단 |
| 전장 | 섬과 바다가 혼재된 군도 전역 |
| 세션 핵심 | 파워 스파이크를 만든 뒤 더 깊이 진입할지 복귀할지 판단 |
| 장비 핵심 | 회수 장비는 소모되며, 빌드 강화는 세션 동안 유지 |
| 작전 핵심 | First in, Last out 기반 선행 강습·항로 개척·전방지원·철수 엄호 |
| 목표 플랫폼 | PC 우선 |
| 코옵 | 장기 확장 후보, 초기 MVP 범위 외 |

### 1.2 프로젝트의 핵심 차별점

이 프로젝트는 다음 결합을 핵심으로 한다.

```text
로그라이트
= 세션 중 빌드 성장과 파워 스파이크

익스트랙션
= 축적한 가치와 손실 위험 사이의 복귀 판단

고속 TPV 메카 액션
= 직접 조준보다 기동·거리·각도·장비 선택에 집중

군도 작전
= 전투 결과가 항로·전선·분견대 지원으로 이어지는 공간적 진행
```

핵심 목적은 **로그라이트에서 완성된 강한 세션을 즉시 끝내지 않고, 익스트랙션의 심층 진입·복귀 선택으로 더 오래 활용하게 하는 것**이다.

## 2. 디자인 필러

### 2.1 기동 자체가 전투

직접 조준 부담을 줄이고, 플레이어는 거리·고도·각도·진입 방향·회피·장비 선택으로 공격 효율을 만든다.

자동 사격은 플레이어 판단을 대체하는 것이 아니라 **조준 부담을 줄여 기동과 포지셔닝 판단의 비중을 높이는 수단**이다.

### 2.2 강하면 더 깊게

빌드가 강하게 완성된 세션일수록 즉시 종료하기보다 더 위험하고 높은 보상을 가진 심층 구역으로 진입할 유인을 만든다.

### 2.3 장비는 소모되고 빌드는 세션 동안 이어진다

회수 장비는 내구도와 수명을 가진 휘발성 자산이다.

반면 빌드 강화는 개별 장비보다 소모품 계열에 연결되어, 장비 파괴나 교체가 즉시 세션 성장 전체를 무효화하지 않게 한다.

### 2.4 복귀는 선택이다

세션은 단순히 끝까지 진행하는 구조가 아니다.

플레이어는 다음을 계속 비교한다.

- 현재 전투력
- 소모품 잔량
- 장비 내구도
- 확보한 회수품 가치
- 전방지원 상태
- 더 깊은 구역의 기대 보상

### 2.5 군도는 배경이 아니라 작전 공간이다

- 바다는 고속 이동 회랑
- 섬은 주요 전투·장비 파밍 노드
- 함대와 대형 함선은 이동형 전투 구획
- 잔해권은 세션 지속 자원 공급처
- 안전 항로와 점령 섬은 아군 영향권
- 작전 항로는 전투 결과를 전방지원으로 연결하는 구조

### 2.6 First in, Last out

플레이어는 위험 해역에 가장 먼저 들어가 전투 공간을 열고, 분견대가 전개할 길을 만든다.

철수 시에는 전방지원 전력이 빠져나간 뒤 마지막까지 이탈을 엄호한다.

이는 플레이어를 단순한 개인 파밍 인원이 아니라 **선도 강습 전력**으로 위치시킨다.

### 2.7 표현은 판단을 돕는다

TPV 카메라, FOV 변화, 추진익, Missile Trail, 경보, HUD, LOD는 단순 장식이 아니라 플레이어가 현재 속도·모드·위협·진입 방향을 읽게 해야 한다.

다만 Gameplay 규칙과 시각 표현의 구현은 분리한다.

## 3. 핵심 플레이 루프

### 3.1 세션 루프

```text
아군 함대권 / 점령 섬에서 출격
        ↓
Cruise로 위험 해역 진입
        ↓
Encounter 탐색
        ↓
Combat 전환 / 자동 사격 / 기동 / 장비 교체
        ↓
구획 무력화
        ↓
섬 장비 또는 함대 잔해 소모품 회수
        ↓
빌드 강화
        ↓
작전 항로 확보 / 필요 시 분견대 전개
        ↓
보급·임시 비축·회수 지원 활용
        ↓
더 깊이 진입할지 복귀할지 판단
        ↓
피습·철수 상황 대응
        ↓
복귀 성공 또는 실패
        ↓
장비·회수품·운용 데이터 정산
        ↓
다음 세션
```

### 3.2 전투 루프

```text
위협 발견
→ Combat 또는 Cruise의 공격 의도 형성
→ 자동 Target Selection
→ 기동으로 딜각 확보
→ 장비별 자동 공격
→ Missile 등 대량 위협 회피·요격
→ 주요 위협 제거
→ 구획 상태 변화
```

### 3.3 감정 루프

| 단계 | 목표 감정 |
|---|---|
| 세션 초반 | 안정적인 기동과 전투 진입 |
| 장비·빌드 성장 | 내가 전투 방식과 효율을 만들어간다는 감각 |
| 파워 스파이크 | 더 깊이 들어가고 싶은 욕구 |
| 자원·내구도 저하 | 잃기 전에 돌아가야 할지 고민 |
| 복귀 성공 | 확보한 가치의 보존 |
| 복귀 실패 | 손실을 감수하되 다시 출격할 수 있는 긴장 |

## 4. 목표 플레이 경험

### 4.1 고속 3D 기동

- 조향 기준, 실제 기체 방향, 카메라 시점과 이동 방향이 일시적으로 분리될 수 있다.
- 고속에서도 횡·상하 이동 Command가 기존 진행 방향 때문에 장시간 무시되지 않는다.
- 입력 해제 시 마지막 제어 방향을 유지한 채 추진 속력과 중력 보정이 점진적으로 풀려 감속·활강으로 이어진다.
- Combat와 Cruise는 향후 동일한 기본 Flight Core 위에서 서로 다른 작전 목적과 표현을 갖는 상위 상태로 확장한다.

상세 기준은 `SYS-110`을 따른다.

### 4.2 자동 사격이지만 수동 판단이 필요한 전투

플레이어는 직접 조준보다:

- 어떤 방향을 보고 있는가
- 어떤 방향으로 이동하는가
- 어떤 장비를 사용하고 있는가
- 어떤 거리·고도·각도를 잡는가
- 언제 집중 공격하거나 이탈하는가

를 통해 공격 결과에 영향을 준다.

상세 기준은 `SYS-120`을 따른다.

### 4.3 다량 Missile 압박

미사일은 배경 연출이 아니라 실제 요격·회피 가능한 위협이다.

이타노서커스형 곡선·교차·시간차 접근·near-miss를 사용하되, 화면에 보이는 주요 Missile은 실제 Gameplay 결과와 연결된다.

상세 기준은 `SYS-130`을 따른다.

### 4.4 파워 스파이크와 손실 긴장

강한 회수 장비와 세션 빌드 강화가 전투력을 끌어올리지만, 소모품과 내구도는 계속 줄어든다.

플레이어는 “지금 가장 강하니 더 들어갈 것인가”와 “지금 돌아가야 가치를 지킬 수 있는가” 사이에서 판단한다.

상세 기준은 `SYS-140`을 따른다.

### 4.5 군도 작전 수행감

전투의 결과는 단순한 적 제거로 끝나지 않는다.

구획 무력화는 항로와 아군 영향권을 바꾸고, 확보한 공간은 분견대의 전개·보급·임시 비축·회수 지원으로 연결된다.

상세 기준은 `SYS-160`을 따른다.

## 5. 핵심 시스템 지도

### 5.1 플레이어 기동 — SYS-110

**아이디어**  
고기동 메카의 기민함을 유지하되 SteeringReference, BodyFacing, ControlledVelocity, GravityVelocity의 관계를 예측 가능하게 만든다.

**목적**  
직접 조준 대신 기동·포지셔닝이 전투 숙련도를 만들게 한다.

**목표 경험**  
즉각적인 3D 이동 Command, 지연 추종하는 기체 방향, 입력 해제 후 감속·활강, 향후 Combat/Cruise 역할 전환.

**목표 성능**  
플레이어 기동 계산은 명시적인 제어 속도와 중력 속도 소유권을 기반으로 하며, 표현용 카메라·애니메이션이 운동 상태를 암묵적으로 변경하지 않는다.

**상세 Canon**  
`SYS-110_플레이어_기동.md`

### 5.2 자동 타게팅·직사 화기 — SYS-120

**아이디어**  
플레이어의 시야와 이동 의도를 무기 Targeting에 사용한다.

**목적**  
직접 조준 부담을 줄이고 기동·장비 선택·딜각 판단에 집중시킨다.

**목표 경험**  
Combat는 화면 중심 정밀 교전, Cruise는 이동 방향 기반 전방 견제를 제공한다.

**목표 성능**  
대량 적 환경에서도 모든 Target을 매번 정밀 검사하지 않고, 공통 후보 인프라와 제한된 후보 평가를 사용한다.

**상세 Canon**  
`SYS-120_자동타게팅_직사화기.md`

### 5.3 미사일 시스템 — SYS-130

**아이디어**  
다수 일반 적 압박을 고속 3D 전투에 적합한 실제 Missile 군집으로 구현한다.

**목적**  
회피·요격·포지셔닝 판단과 고속 전투의 대표적 시각 정체성을 동시에 만든다.

**목표 경험**  
이타노서커스형 곡선·교차·시간차 접근·Overshoot·Reacquire·near-miss.

**목표 성능**  
대량 Missile이 존재해도 개별 Player Search와 불필요한 고비용 판단을 반복하지 않으며, Gameplay와 대량 시각 표현의 비용을 분리한다.

**상세 Canon**  
`SYS-130_미사일_이타노서커스.md`

### 5.4 세션·장비·빌드·익스트랙션 — SYS-140

**아이디어**  
휘발성 회수 장비와 세션 한정 빌드 강화를 결합하고, 그 가치를 익스트랙션 판단으로 연결한다.

**목적**  
로그라이트의 파워 스파이크를 더 오래 활용할 수 있게 한다.

**목표 경험**  
장비 교체와 강화로 강해질수록 더 깊이 들어가고 싶지만, 소모품·내구도·회수품 가치가 복귀 압박을 만든다.

**목표 성능**  
장비 종류가 늘어도 소모품 계열과 공통 시스템을 재사용해 콘텐츠·구현 복잡도의 폭증을 억제한다.

**상세 Canon**  
`SYS-140_세션_장비_빌드_익스트랙션.md`

### 5.5 군도 작전·전방지원 — SYS-160

**아이디어**  
군도 전장을 구획 무력화·항로 개척·전방 비축·철수 엄호가 이어지는 작전 공간으로 만든다.

**목적**  
전투 결과를 공간·전선·아군 지원의 변화로 연결한다.

**목표 경험**  
First in, Last out, 조건부 전방지원, 분견대 피습과 철수 판단, 섬·함대·잔해의 서로 다른 작전 가치.

**목표 성능**  
비활성 군도 전체를 항상 시뮬레이션하지 않고, 실제 활성화와 공통 Runtime은 `ARCH-100`에 위임한다.

**상세 Canon**  
`SYS-160_군도작전_전방지원.md`

## 6. 공통 기술 목표

공통 기술 구조는 `ARCH-100`이 소유한다.

프로젝트 수준에서 필요한 목표만 다음과 같이 정의한다.

### 6.1 대량 객체

다수 일반 적·Missile·Projectile이 존재해도 전체 객체 수에 비례해 모든 고비용 판단을 반복하지 않는다.

### 6.2 프레임타임 안정성

평균 FPS뿐 아니라 특정 순간에 Spawn, 공격, 폭발, VFX가 겹치면서 발생하는 CPU·GC·Physics spike를 통제할 수 있는 구조를 목표로 한다.

### 6.3 계산 대상·빈도·고비용 실행량 제한

성능 최적화의 우선순위는 다음 방향을 따른다.

```text
불필요한 연산 제거
→ 연산 대상 수 축소
→ 연산 빈도 축소
→ 공통 계산 공유
→ 고비용 실행량 상한
→ 병렬화
→ 반복 시각 작업 GPU 이전
```

### 6.4 Gameplay와 Visual 분리

Gameplay 결과와 대량 시각 표현은 같은 객체 구조에 1:1로 묶이지 않아도 된다.

시각적 밀도를 높이기 위해 Gameplay correctness를 희생하지 않고, Gameplay correctness를 유지하기 위해 모든 표현을 CPU Gameplay 객체로 만들지도 않는다.

### 6.5 향후 멀티플레이 확장성

초기 기준은 Host-authoritative 구조이며, 향후 최대 4인 확장을 고려한다.

완전 lockstep 결정론이나 ZoneOwner 분산 권위는 현재 프로젝트 목표가 아니다.

### 6.6 수치 목표

현재 소스에는 프로젝트 전체의 확정된 FPS·해상도·하드웨어 Target이 없다.

따라서 숫자를 임의로 추가하지 않는다.

구체 Budget은 `ARCH-100`과 각 Prototype Profiling에서 확정한다.

## 7. 세계관 핵심 전제

프로젝트 이해에 필요한 세계관 전제만 요약한다.

- 심향물리계는 여러 세계에 걸쳐 작용하는 공통 물리축이다.
- 각 세계는 별도의 인과적 시공간과 실제 역사를 가진다.
- 정상상태에서는 각 효과의 인과적 귀속이 보존된다.
- 최초 사건은 이 귀속 경계가 국소적으로 붕괴한 사건이다.
- 군도는 다른 세계의 인과가 게임 세계의 현실에 직접 간섭할 수 있는 영역이다.
- 인과폐색은 자신의 인과적 기준을 안정적으로 판별하지 못하게 되는 현상이다.
- 리마니움은 강한 폐색 조건에서 형성되는 특이 안정 금속상이다.
- 플레이어는 군도에 선행 진입하는 정규군 강습 전력이며, 적성 장비를 제한적으로 회수·운용한다.

상세 설정은 `WORLD-100_세계관_Canon.md`를 따른다.

## 8. MVP와 검증 우선순위

MVP는 콘텐츠 완성보다 **핵심 가설을 위험도가 높은 순서로 검증**하는 데 목적이 있다.

### 8.1 1단계 — 기동

검증 질문:

> 자동 사격이 존재하는 상태에서 고속 3D 기동 자체가 반복할 가치가 있는가?

담당 Canon: `SYS-110`

### 8.2 2단계 — 공격 의도와 자동 타게팅

검증 질문:

> Combat의 화면 중심과 Cruise의 이동 방향 기반 공격 의도가 플레이어에게 자연스럽게 읽히는가?

담당 Canon: `SYS-120`

### 8.3 3단계 — 대량 위협과 전투 Runtime

검증 질문:

> 다량 적·Missile 환경에서 전투 밀도와 프레임 안정성을 동시에 유지할 수 있는가?

담당 Canon: `ARCH-100`, `SYS-130`

### 8.4 4단계 — 세션·익스트랙션

검증 질문:

> 빌드가 강해진 순간에 더 깊이 들어갈지 복귀할지 실제 고민하게 되는가?

담당 Canon: `SYS-140`

### 8.5 5단계 — 군도 작전과 전방지원

검증 질문:

> 구획 무력화→항로→분견대→철수의 흐름이 단순한 파밍 보조가 아니라 작전 수행감으로 이어지는가?

담당 Canon: `SYS-160`

### 8.6 후속 확장

- 콘텐츠 다양화
- 대형 함선 Encounter
- 분견대 성장 확장
- 더 복잡한 세계관 노출
- 코옵

후속 확장은 핵심 가설 검증 이후 판단한다.

## 9. 프로젝트 수준 리스크

### 9.1 고속 기동 자체가 재미없을 위험

가장 우선적인 프로젝트 리스크다.

기동이 재미없으면 자동 사격과 군도 전장도 핵심 차별점이 되기 어렵다.

대응은 `SYS-110` Prototype 검증을 최우선으로 둔다.

### 9.2 자동 사격이 수동성을 만들 위험

플레이어가 “게임이 알아서 싸운다”고 느끼면 전투 개입감이 약해진다.

따라서 기동·딜각·장비 교체·Targeting Intent가 공격 결과에 실제 영향을 주어야 한다.

### 9.3 시스템 수가 장르 초점을 흐릴 위험

전선·분견대·함재 메카·메타 성장 등은 모두 메카 액션의 핵심 루프를 지원해야 한다.

독립적인 RTS나 함대관리 게임으로 확대하지 않는다.

### 9.4 콘텐츠 제작량이 폭증할 위험

장비·적·함선·구획 종류를 늘리는 방식만으로 반복성을 해결하지 않는다.

공통 시스템, 소모품 계열, 적성 객체 아키텍처, 군도 공간 역할을 재사용한다.

### 9.5 시각 밀도와 성능이 충돌할 위험

다수 Missile, Drone, Projectile, 수면 효과, VFX가 핵심 연출이지만 동시에 성능 병목이 될 수 있다.

Gameplay Simulation과 Visual을 분리하고 실제 Profiling에 따라 비용을 관리한다.

### 9.6 코옵이 초기 구조를 과도하게 복잡하게 만들 위험

최대 4인 확장성을 고려하되 초기 MVP에 온라인 코옵 전체 구현을 요구하지 않는다.

## 11. Open Decisions

본 절에는 **여러 Canon 문서에 동시에 영향을 주는 결정만** 둔다.

개별 시스템의 수치·튜닝·구현 후보는 해당 문서의 Open Decisions에서 관리한다.

### 11.1 프로젝트 성능 Target

아직 프로젝트 전체의 최종 목표 FPS·해상도·최소 하드웨어가 확정되지 않았다.

프로토타입 Profiling 이후 프로젝트 수준 목표를 결정한다.

### 11.2 코옵

코옵은 장기 확장 후보지만:

- 지원 여부
- 개발 시점
- 최대 인원
- 세션 구조 변화

는 아직 프로젝트 수준 미정이다.

현재 Architecture는 Host 기반 최대 4인 확장을 고려하되 실제 온라인 코옵을 MVP 전제로 하지 않는다.

코옵을 다시 판단할 시점과 채택 기준은 아직 정하지 않았다. 지원 여부를 결정하기 전에 작성자가 이 조건을 먼저 정한다.

### 11.3 최종 콘텐츠 범위

다음은 핵심 시스템 검증 이후 확정한다.

- 장비군의 최종 수
- 적 유형과 대형 함선의 수
- 군도 전체 규모
- 분견대 성장 깊이
- 스토리·세계관 노출량
